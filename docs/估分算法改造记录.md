## 二、P0 数据链修复（细节）

### 2.1 同一份成绩被算两次

- 导入/上传是同时写 `papers` + `records` 的（`app.js` submitImport / analyzeUpload）。
- `progress.js` 原来在"该科没有判过对错的题"时把 records **全部再算一遍**，没有按 `paperId` 去重。
- **实测**：数学真题 100/150 → 等效率被算成 54.2%（应为 66.67%），因为 record 侧来源丢失、被当校内卷打了 0.72 折，而且 recency 权重还翻倍。

**修法**：逐份判断 —— 有对应 paper 的 record 跳过，独立 record 才计入；来源从 `record.kind` / `importData.source` 还原。

**同时**：三个写入点（手动导入 / 上传识别 / 拍照读题）都补了 `kind` 字段，新数据不再丢来源。

### 2.2 一刀切丢数据

旧代码把上面那段包在 `if (!nQuestions)` 里 —— 该科只要有 1 题判过对错，其他纯成绩记录就**全部被丢弃**。改成逐份判断后，这个问题同时解决。

### 2.3 保存校正破坏原始分

旧代码 `fullScore × right / qs.length` 三个错：忽略每题分值、未知题当错、结果回写进原始 record。

**修法**（`app.js: recomputeScoreFromQuestions`）：
- 有题分 → 按分值加权（partial credit）
- 未判定 → 不计入分母
- 全未判定 → 不动分数
- 原始分另存 `scoreOriginal`，永不覆盖

### 2.4 六科汇总越界（`analyzeTotal`）

AI 的分没夹 [0,满分]、`r.total` 直接采信、强制 `missing:[]`。
**修法**：以本地证据为基准夹取（±15%）、总分由六科加总、缺科如实记录。

## 三、P1 证据层（核心算法升级）

### 3.1 三个硬伤 → 三个解法

| 旧硬伤 | 解法 | 依据 |
|---|---|---|
| 得分率有界 (0~1)，直接平均被边界压缩 | **logit 尺度** | 可加、可做贝叶斯更新 |
| 题少的卷子和题多的卷子话语权一样 | **每卷自带方差**（delta method：`1/(n·p(1-p))`）| 标准结果 |
| 近期权重用"排名式"（最早1倍→最新2倍），不看真实间隔 | **时间半衰期** `w = 0.5^(Δt/H)`，H=120 天 | 遗忘/水平变化尺度 |

### 3.2 经验贝叶斯收缩（核心）

```
加权均值  ȳ = Σ(precᵢ·wᵢ·θᵢ) / Σ(precᵢ·wᵢ)
标准误    SE² = 1 / Σ(precᵢ·wᵢ)
收缩权重  w = τ² / (τ² + SE²)
后验      θ̂ = w·ȳ + (1−w)·μ_prior
```

**实测梯度**（这才是它该有的样子）：
```
1卷×5题   w=0.423 → 60.1%   ← 数据少，靠近先验
1卷×25题  w=0.778 → 66.3%
5卷×25题  w=0.946 → 68.5%   ← 数据多，听数据
10卷×25题 w=0.972 → 68.9%
```

### 3.3 本轮修的两个真 bug

**① 满分时方差爆炸**

delta method 的 `1/(n·p(1-p))` 在 p→1 时爆炸 → **考满分的学生 w=0.0015，被完全忽略**，直接返回先验 55%。

修法：加一平滑 `p' = (k·p+1)/(k+2)`，k=2n。修后 w=0.22，满分卷重新有话语权。

**② 先验方差 τ² 偏小**

最初 `τ²=0.36`（学生间差异 ±13% 得分率），导致单卷满分被先验拉到 88.8 分。
改为 `τ²=1.6`（±28%），更符合高三真实分布（40%~95% 都有人）。

## 四、P2 充分度分级

**旧问题**：`confidence = 1−e^(−题数/30)` 只看题数 → "同一套题做 50 遍"显示高置信度。

**新口径**（四维 + 惩罚）：
```
raw = 题量×0.45 + 难度覆盖×0.30 + 来源多样性×0.15 + 时间跨度×0.10
惩罚：来源单一 ×0.75；全挤两周内 ×0.85
分级：≥0.72 high / ≥0.40 mid / 否则 low
```

**实测**：
```
3 题 1 卷           → low  (0.027)
同源 50 题（10 卷） → mid  (0.482)   ← 不再是 high
充分（60题/3来源）  → high (1.0)
```

> 加权和 → 加权和×惩罚因子 的改动，是被测试 P2-1b 抓出来后做的：
> 原来的加权和让"同源 50 题"拿 0.756（high），一项强弥补了另一项弱。

## 五、P3 浙江等级赋分（口径修正）

### 5.1 官方依据

浙江省教育考试院《浙江省2022年高考招生相关政策问答》问答 2/6：
https://www.zjzs.net/art/2022/6/19/art_159_7037.html

- 语数外各 150，**按卷面得分**计入
- 选考各 100，**按等级赋分**，起点 40 分
- 20 个赋分区间，累计比例：`1,3,6,10,15,21,28,36,43,50,57,64,71,78,84,89,93,96,98,100`
- 区间内等比例转换、四舍五入；保障基数 6.5 万人

### 5.2 实现

- `DB.ZJ_GRADE_BANDS`：官方 20 区间（可审计）
- `DB.zjGradeFromPercentile(rankPct)`：位次 → 赋分（区间内线性插值）
- `DB.zjGradeRange(rankPct, uncertainty)`：位次 ± 不确定度 → 赋分区间
- `DB.isZhejiang(goal)` / `DB.isGradeAssigned(subject, 省份)`
- progress.js：选考输出**赋分**（40~100），语数外保持原始分

**实测映射**：
```
前 0.1% → 100    前 1% → 97    前 10% → 88
前 50%  → 70     前 99% → 42
```

### 5.3 技术（浙江特有 7 选 3）

- `PROVINCE_SELECTABLE`：浙江 7 门 / 其他省 6 门
- 技术满分 100、难度基准 0.84、16 个教材章节（信息技术+通用技术，浙教版）
- 问卷选科列表**按省份动态生成**（城市输入变化时重建，尽量保留已勾选）

### 5.4 两个被测试抓出的 bug

**① `province` 字段名不对**：省市实际存在 `goal.city`（"浙江杭州"），只看 `goal.province` 会让**浙江判断永远为 false** → 赋分静默失效。
`isZhejiang()` 现在同时看两个字段。

**② P3/P4 测试断言错误**：我最初断言"总分 = 525"（原始分口径），但选考走赋分后应为**语数外原始分 + 选考赋分**。已修正断言。

## 六、P4 预测区间

### 6.1 三块误差合成

```
SE_total = sqrt(SE_measure² + SE_model² + SE_future²)
SE_measure —— 现有证据估"现在水平"的不确定度
              = sqrt(p(1-p)/n) × 惩罚(难度未判 +30% / 覆盖未判 +20%) × 满分
              下限：满分的 2%（模型本身不完美）
SE_model   —— k/τ/efficiency 是拍的，按剩余空间比例给
SE_future  —— 剩余时间内的实际投入/状态不可知，时间越长越大
```

### 6.2 实测行为（都是测试验证过的）

```
1 卷 5 题（数据少）  → 区间宽 39.8，SE=37.05
10 卷 25 题（数据多）→ 区间宽 31.5，SE=11.87    ← 数据少→区间宽 ✓
难度未判             → SE 26.08 → 35.57（变大）  ✓
离高考 30 天 vs 600 天 → SE 26.30 → 28.20      ✓
```

### 6.3 总分区间：方差合成

```
SE_total = sqrt(Σ SEᵢ²)
```
单科 SE 之和 140.63 vs 合成 58.58 —— **不能简单相加**（会夸大），也不能忽略（会假装没误差）。
已验证 `≤ 750`、`包含预测点`。

## 七、P5 前瞻回溯（`js/backtest.js`，新建）

### 7.1 三步

```
① 存档：每次估算原样保存（预测值/区间/输入摘要），**不重算**
② 真值：考完录入实际分
③ 比对：MAE / RMSE / 有符号偏差 / 区间覆盖率（PICP）/ 分科指标
```

### 7.2 配对规则（防偷看未来）

- 只用真值**之前**最近的那次预测
- 真值之后才做的预测**不参与配对**（测试 P5-2d 验证）
- 预测必须覆盖该科目（总分真值 → 必须有 total；单科真值 → 必须有该科预测）

### 7.3 诚实度判断

```
区间覆盖率 ≥85% → good     ≤70% → overconfident（区间在吹牛）
样本 <5 对      → 不给结论
```

**在拿到真实回溯数据之前，界面上不出现任何"准确率 XX%"。**
