# 构建 Windows 安装包

本项目用 **electron-builder + NSIS** 出安装包。目标：用户下载一个 `.exe`，双击、下一步、完成，就能用。

---

## 成品

| 文件 | 大小 | 内容 |
|---|---|---|
| `xuetu-slim-setup-1.1.0.exe` | 84 MB | 核心功能，不含 DeepTutor |
| `xuetu-full-setup-1.1.0.exe` | 284 MB | 含 DeepTutor 运行时（Python + Node + 前端） |

安装后分别占 **287 MB** / **994 MB**。

---

## 快速构建

```bash
# 1. 装构建依赖（只要一次）
npm i -D electron-builder

# 2. 出精简版安装包
npx electron-builder --win nsis --x64

# 3. 出完整版（带 DeepTutor）
XUETU_VARIANT=full npx electron-builder --win nsis --x64
```

产物在 `dist/` 下。

> PowerShell 里设环境变量用 `$env:XUETU_VARIANT='full'`。

## 踩过的坑（重要，改配置前先读）

### ① 主进程模块必须能在 asar 里被 require

主进程用**相对路径** require 这些文件：

```js
require('./electron-workbuddy.js')
require('./electron-tools.js')
require('./electron-agent.js')
```

如果只把它们放进 `extraResources`（→ `resources/` 目录），`asar` 里就没有这些文件，
运行时报：

```
Error: Cannot find module './electron-workbuddy.js'
Error occurred in handler for 'workbuddy:models': No handler registered
```

**后果很严重**：「用 WorkBuddy 跳过填 Key」这个免费卖点会**直接失效**。

正确做法是 `asarUnpack` —— 文件既进 asar（可 require），又落地成真实文件（可 spawn）：

```js
files: [ ..., 'electron-workbuddy.js', 'electron-tools.js', ... ],
asarUnpack: ['electron-scene.cjs', 'workbuddy-bridge.cjs', ...],
afterPack: (ctx) => { /* 再复制一份到 resources/ 兼容旧路径 */ }
```

### ② `electron-workbuddy.js` 里有 `require('electron')`

`workbuddy-bridge.cjs` 用**纯 node.exe** 跑（不能是 Electron，否则模块解析带上 asar 补丁会崩），
但它 require 的 `electron-workbuddy.js` 顶部有 `require('electron')` 取 `ipcMain` —— 纯 node 下必然失败。

这是**已知的架构限制**，影响可控：

- 主程序的 WorkBuddy 走 **IPC**，不依赖这个桥
- 前端没有任何地方引用 8790 端口
- 该桥只为 DeepTutor 后端提供 HTTP 形式的 WorkBuddy 能力

所以 `deeptutor-runtime.cjs` 里做了优雅降级：识别到 `Cannot find module 'electron'` 就打一行说明，不刷堆栈。

### ③ `winCodeSign` 解压失败（Windows 权限）

第一次构建可能报：

```
ERROR: Cannot create symbolic link : 客户端没有所需的特权
```

原因是压缩包里含 macOS 的符号链接。绕过：

```bash
7za x winCodeSign-2.6.0.7z -o<CacheDir> -y -snl
```

`-snl` 关闭符号链接处理。然后 `app-builder download-artifact --name winCodeSign-2.6.0`
会直接返回缓存路径，不再联网。

### ④ 复用本地 Electron，别重新下载

把 `node_modules/electron/dist` 压成 `electron-v33.4.11-win32-x64.zip`
放进 `%LOCALAPPDATA%\electron\Cache`，再配 `electronVersion: '33.4.11'`，
构建时就不会去下载 100 MB+ 的包。

### ⑤ `deeptutor-runtime.cjs` 不能靠 `process.cwd()` 找运行时

曾经的第 ④ 号候选是 `process.cwd()/runtime/deeptutor`，隐患是：
用户从任意目录启动 exe，就会去捡那个目录下的 `runtime/deeptutor`。
精简版本该「跳过」，结果因为 cwd 恰好指向一个含 runtime 的目录而硬启动，然后报错退出。

现在打包态只认 `resources/`：

```js
const isPackaged = !!process.resourcesPath && !String(process.resourcesPath).includes('node_modules');
```

### ⑥ 构建目录不能有安全软件会拦 Electron 的路径

本机 `C:\Users\<用户>\项目2` 这个目录下 Electron 会被安全软件拦截
（退出码 `-2147483645`，`electron.exe --version` 都跑不了）。
构建要在别的目录进行（比如 `D:\XueTuBuild`）。

## 验证清单

出包后**必须**实际装一遍，不能只看构建成功：

```bash
# 静默安装到临时目录
xuetu-slim-setup-1.1.0.exe /S /D=D:\TestInstall

# 启动并带调试端口
D:\TestInstall\学徒.exe --remote-debugging-port=9999

# 检查 stderr 不该出现
#   Cannot find module
#   No handler registered

# 检查窗口
#   visible=true 且在屏幕内（不是 -32000,-32000）

# 卸载
"D:\TestInstall\Uninstall 学徒.exe" /S
```

统计功能可以用 CDP 点真实按钮验证，见项目根目录 `_verify_usage_ui.cjs`。
